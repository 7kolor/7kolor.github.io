# 7Kolor 六步开发决策流程 · 网站改造设计方案

> 本文档是网站围绕「六步开发决策流程」进行改造的完整设计方案。
> 涵盖：首页设计、六个环节详情页模板、报告展示模块、信息架构。

---

## 1. 总体设计原则

### 1.1 核心叙事

**「先洞察，后开发」**——这是整站的第一叙事。

独立开发者（IA/Solo Dev）的三大困境：
- 闷头写代码 → 做出来没人用
- 看别人做什么火就抄 → 陷入红海
- 上线后才知没人买单 → 返工成本极高

7Kolor 的价值：**在动手写代码之前，先搞清楚方向。**

### 1.2 六步流程 = 站点骨架

六步不是六个独立的碎片，而是从 0 到 1 的完整决策链路：

```
① 发现机会 → ② 收集信号 → ③ 深挖问题 → ④ 验证假设 → ⑤ 最后把关 → ⑥ 验证价值
```

任何页面（首页、报告、归档、单篇内容）都隶属于或映射到这条链路。

### 1.3 设计语言

- **气质**：懂技术的「军师」，直接、不啰嗦、数据驱动
- **视觉**：干净、信息密度高但不杂乱（沿用当前 cyan→blue 技术风）
- **动效**：克制，用于引导顺序感
- **双语**：中文为主，英文同步（沿用现有 data-zh/data-en 机制）

## 2. 首页设计方案


### 2.2 六步流程图展示方式

**推荐：横向时间线**（桌面端）

- 桌面端（≥960px）：六步横排成一条带箭头的递进链
- 平板（640~960px）：三列 × 两行
- 移动端：垂直瀑布流（从上到下，箭头向下）

每步节点内容：
```
┌─────────────┐
│    ①         │  ← 大编号（Gradient 圆）
│ 发现机会      │  ← 环节名
│ Stop fork,   │  ← Slogan（mono, 小字号）
│ start gap    │
│ 核心问题：    │
│ 做什么能赚钱？ │
└─────────────┘
```

视觉要点：
- 六步用「蓝→青」渐变色系，按步骤从冷到暖渐进（或统一色系 + 编号强调）
- 每步卡片 hover 抬起 + 显示「查看详情 →」
- 六步之间用箭头/连接线，强调**顺序依赖**而非碎片

### 2.3 Hero Slogan 轮播

六条 Slogan 每 2~3 秒轮播一条：

```
Stop fork repo, start find gap.
Stop git push, start data pull.
Stop pull request, start pain research.
Stop commit, start converse.
Stop deploy, start discover.
Stop Merge, Start Market.
```

轮播带进度条指示器，2 秒切换。首屏默认显示「先洞察，后开发」大标题 + 第一条 Slogan。

### 2.4 视觉节奏

| 区块 | 节奏 |
|------|------|
| Hero | 大留白，中心对齐，品牌大字 |
| 数据底盘 | 紧凑通栏，3 列指标 |
| 六步总览 | 全宽视觉焦点，横向递进 |
| 最新一期 | 突出 1 张大卡片 |
| 六步入口 | 3×2 网格卡片 |
| 报告导航 | 周报 + 专项两个模块 |
| 服务 | 高亮卡片 |

## 4. 报告展示模块

### 4.1 报告体系

| 类型 | 节奏 | 覆盖 |
|------|------|------|
| 📰 每周周报 | 每周 1 期 | 六环节全链热点动态 |
| 📊 专项报告 | 定期更新 | 每环节 1 份深度报告（6 个专项） |

### 4.2 首页展示

```
┌─ 最新一期（突出显示）─────────────────────┐
│ 📰 2026 W34 周报                          │
│ AI 编程可信度危机与定价获客               │
│ [阅读全文 →]                              │
└──────────────────────────────────────────┘
┌─ 专项报告（按六环节分类）────────────────────┐
│ ①发现机会专项 ②收集信号专项 ... ⑥验证价值专项 │
│ (六张分类卡片，每张可跳转对应专项列表)      │
└──────────────────────────────────────────┘
```

### 4.3 分类筛选逻辑

- **按环节筛选**：`#discover` `#signal` `#pain` `#assume` `#final` `#market`
- **按报告类型**：`周报 Weekly` / `专项 Analysis`
- **归档页**支持双维度筛选

### 4.4 报告内部结构（统一模板）

每份报告坚持以下结构：

```
1. 概览（1 段话说清本周/本期最大信号）
2. 六环节分段（①→⑥，每条标注数据源）
3. 原始证据（帖子/讨论链接，注明来源平台）
4. 数据透视（统计图表）
5. 决策建议（收尾：可直接执行的 Action Items）
```

### 5.2 用户访问路径

**路径 A（新访客 · 认知）**
`/` → Hero 六步总览 → 进入某个环节 → 看书读报告 → 订阅/联系

**路径 B（有想法的开发者）**
```
有想法 → 首页看六步 → 发现自己处于「②收集信号」→
进入 step-2 → 看该环节方法论 + 专项报告 → 看最新周报相关部分 → 联系定制分析
```

**路径 C（老读者/归档）**
```
首页「最新一期」→ 阅读周报 → 按六环节分类查看专项 → 归档
```

## 6. 技术落地建议

### 6.1 目录结构

```
/
├── index.html              # 首页（含六步总览、周报、专项导航）
├── steps/
│   ├── step-1/index.html
│   ├── ...
│   └── step-6/index.html
├── weekly/                 # 周报（现有）
├── analysis/               # 专项报告（新增，每环节一目录）
│   ├── discover/
│   ├── signal/
│   ├── pain/
│   ├── assume/
│   ├── final/
│   └── market/
├── docs/six-step-design.md # 本文档
└── assets/css/main.css
```

### 6.2 构建系统扩展

在 `scripts/build_site.py` 的 `MODULES` 中新增：

```python
MODULES = {
    "weekly":   ("weekly",   "📰 每周周报", "Weekly Intelligence", ...),
    "analysis": ("analysis", "📊 专项报告", "Special Report", ...),
    ...
}
```

并为 `analysis/` 增加六环节分类字段：`step: 1|2|3|4|5|6`。

### 6.3 渐进实施顺序

1. 建立六个环节页面（静态 + 双语）
2. 改造首页：Hero Slogan 轮播 + 六步总览 + 六步入口卡片
3. 扩展报告体系：新增 analysis 目录 & 卡片分类
4. 全局导航与面包屑
5. 后续：交互筛选、搜索、更多数据可视化
